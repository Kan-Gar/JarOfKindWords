# Баночка хороших слов

Статический цифровой подарок: уютная ночная сцена, стеклянная баночка и 158 писем: 150 записок пяти категорий, 6 очень редких намёков и 2 финальных признания. Без регистрации, сервера, ключей API и платных сервисов.

## Запуск

Нужен Node.js 22.12+ (проверено на 24.22.1), npm и современный браузер.

```bash
npm ci
npm run dev
```

В новом проекте также работает `npm install`; для воспроизводимой установки используйте `npm ci` с сохранённым `package-lock.json`. Если домашний каталог недоступен для записи в облачной среде:

```bash
npm ci --cache /workspace/.cache/npm --no-audit --no-fund
```

```bash
npm run build    # TypeScript и production-сборка в dist/
npm run preview  # локальная проверка production-сборки
npm test         # 17 тестов данных, выбора записок и сохранения
npm run test:e2e # 12 браузерных сценариев Chromium; запускает dev-сервер
```

Для браузерных тестов по умолчанию нужен `/usr/bin/chromium`. Другой установленный Chromium можно передать через `CHROMIUM_PATH=/path/to/chromium npm run test:e2e`. Браузерные тесты не устанавливают браузер автоматически. В текущей облачной среде он уже доступен. Порт тестового сервера — 5173; существующий dev-сервер на этом порту переиспользуется.

## Возможности

- Первый визит с приветствием; повторный просмотр из настроек.
- Авторская пиксельная сцена PixiJS: многослойное стекло, крышка, ленточка с сердечком, бумажки, луна, книги, лаванда и свеча.
- GSAP-последовательность: сжатие и встряхивание, поднятие крышки, полёт по кривой Безье, разворачивание бумажной карточки. Последующие открытия быстрее.
- Пять категорий, случайный режим и выбор настроения. Редкие записки получают золотую рамку и более яркое свечение.
- Избранное с просмотром, открытием и удалением через сердечко.
- Версионированное сохранение, история прочитанного, прогресс циклов и настройки.
- Синтезированные Web Audio API звуки стекла, шелеста и волшебства. По умолчанию включены; воспроизведение начинается после первого нажатия. Выключение сохраняется.
- DOM-интерфейс с клавиатурным управлением, native dialog, фокусом, доступными подписями, прокруткой длинных сообщений.
- Safe area, `dvh` и резервные размеры, ограничение DPR до 2, сокращение частиц при медленных кадрах, остановка сцены при скрытии вкладки, системное уменьшение движения.
- Упрощённая CSS-баночка, если WebGL недоступен. Избранное и записки работают без графического ускорения, звука и доступного localStorage.

## Как выбираются записки

`NoteManager` использует взвешенный выбор **без возвращения**. Вес = `weight` × коэффициент редкости (common: 1, rare: 0.35, special: 0.12, confession: 0.006). Это относительные веса, а не фиксированный процент: вероятность меняется по мере опустошения цикла. Даже особенная записка обязательно встретится за полный цикл.

У случайного режима и каждой категории независимая очередь. Завершение категории обновляет только её очередь. Последняя показанная записка исключается, если есть другая доступная. При переключении между независимыми режимами уже прочитанная в другом режиме записка может встретиться снова — ограничение повторов действует внутри выбранного цикла.

Сохранение `kind-words-jar.v1` содержит только идентификаторы избранного и историю, а не копии текстов. Неизвестные идентификаторы удаляются при загрузке, новые записки добавляются в очередь. Повреждённый JSON сбрасывается к безопасному начальному состоянию, неизвестная версия не интерпретируется. Если запись запрещена, приложение продолжает работать в памяти.

## Добавить или изменить сообщения

Редактируйте `src/data/notes.json`. Пример объекта:

```json
{
  "id": "support_021",
  "category": "support",
  "text": "Можно немного выдохнуть. Ты не обязана всё успеть прямо сейчас.",
  "rarity": "common",
  "weight": 1
}
```

Категории: `support`, `compliment`, `humor`, `warmth`, `special`. Редкость: `common`, `rare`, `special`, `confession`. ID должен быть уникальным и оставаться стабильным при исправлении текста; `weight` — положительным числом. Тексты вставляются через `textContent`, не как HTML. Для сотен новых записок менять алгоритм не нужно. После изменения количества обновите ожидаемые числа в тестах набора данных; счётчик интерфейса вычисляется автоматически. Затем выполните `npm test` и `npm run build`.

Персонализировать подарок можно в текстах JSON и приветствии в `src/components/UIManager.ts`. Начальные записки не содержат выдуманных личных воспоминаний, имён и обязательного романтического подтекста.

## Публикация на GitHub Pages

1. Сохраните проект в репозитории `Kan-Gar/JarOfKindWords` и отправьте его в ветку `main`.
2. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Запустится `.github/workflows/deploy.yml` (при необходимости запустите **Publish GitHub Pages → Run workflow** вручную во вкладке Actions).
4. Workflow устанавливает зависимости по lockfile, запускает тесты, собирает проект и размещает `dist/`.
5. После успешного deployment откройте адрес, который выдаст Pages. Для этого репозитория стандартный адрес — `https://kan-gar.github.io/JarOfKindWords/`. Это ожидаемый адрес после публикации, сайт из этой задачи ещё не опубликован.
6. Выполните проверки из `MANUAL-QA.md`, затем отправьте HTTPS-ссылку через Telegram.

`base: './'` в `vite.config.ts` позволяет загружать файлы из подкаталога GitHub Pages и с корня других статических хостингов. Клиентского роутера нет, серверные rewrite-правила не нужны. Для Cloudflare Pages / Netlify: команда `npm run build`, каталог `dist`.

В `index.html` уже есть Open Graph и изображение `public/assets/social-card.png` (1200×630). `og:image` и `og:url` используют предполагаемый GitHub Pages URL выше. При другом домене замените их на **абсолютные HTTPS URL** до сборки. Предпросмотр Telegram проверяется после реальной публикации и может кэшироваться. Не указывайте localhost в метаданных.

## Структура

- `src/core/SceneManager.ts` — PixiJS-сцена, слои и цикл отрисовки.
- `src/core/StorageManager.ts` — валидация и хранение состояния.
- `src/core/types.ts` — категории и типы данных.
- `src/components/JarController.ts` — блокировка взаимодействий и переходы.
- `src/components/UIManager.ts` — приветствие, записка, настроение, настройки и избранное.
- `src/systems/NoteManager.ts` — выбор и циклы записок.
- `src/systems/AnimationManager.ts` — анимационные последовательности.
- `src/systems/ParticleSystem.ts` — ограниченные частицы и адаптивное качество.
- `src/systems/AudioManager.ts` — собственный синтез звуков; аудиофайлы не требуются.
- `src/styles/main.css` — адаптивный интерфейс и упрощённая графика.
- `public/assets/` — иконка и Open Graph, включая редактируемый SVG-исходник.

Графика сцены процедурная, без загружаемых текстур: атлас изображений здесь не требуется. Дополнительные фильтры и текстуры при каждом открытии не создаются.

## Проверено и ограничения

Проверены TypeScript, production-сборка, 17 тестов логики и 12 браузерных сценариев Chromium: первый/повторный визит, все категории, быстрая серия касаний, избранное, перезагрузка, длинная записка, 320×480, уменьшение движения, отсутствие localStorage / AudioContext / WebGL, повторное открытие вкладки, десктоп и клавиатура. Полные циклы и независимость категорий проверены тестами логики.

- Настоящий iPhone, Safari, Telegram WebView, фактические 60 FPS, расход батареи и звук на устройстве **не проверены**. План ручной проверки: `MANUAL-QA.md`.
- Публикация, публичная HTTPS-ссылка и Telegram Open Graph ещё не проверены. Автоматический workflow подготовлен, но из этой задачи не запускался.
- Избранное хранится локально и может исчезнуть при очистке данных. Safari и Telegram могут иметь разные хранилища; синхронизации, экспорта и импорта нет.
- Нет фоновой музыки, датчика движения и пасхалок: они необязательны для первой версии.
- Сцена — законченная компактная процедурная пиксельная иллюстрация, а не детализированный рисованный спрайтовый набор. Для дальнейшей художественной доработки можно заменить графические слои без изменения выбора записок и интерфейса.
- В офлайн-режиме первый запуск не поддерживается: service worker не добавлен. После загрузки основные функции не требуют API.

## Персональная волшебная почта

Сцена оформлена как кабинет волшебной школы: арочное окно, замок вдали, старые книги, пергамент и сургучная печать. Белая почтовая сова — собственная процедурная иллюстрация, без заимствованных кадров и звуков из фильмов. С вероятностью 18% она приносит следующее письмо; ещё 30% открытий выполняет волшебная палочка; если шесть открытий подряд прошли без совы, седьмое письмо приносит сова. Доставка не связана с редкостью текста. При системном уменьшении движения полёт пропускается, текст и подпись доставки остаются.

Шесть признаний имеют редкость `confession` и находятся среди особенных писем. Их начальный вес в 20 раз меньше обычной `special`-записки. Это взвешенный цикл без повторов, а не фиксированный процент: ближе к концу цикла оставшиеся редкие письма встречаются чаще и не теряются навсегда. Отдельной кнопки для раскрытия признаний нет.

Категория Motivation удалена. Существующие избранные и история сохраняются, удалённые ID очищаются, настроение Motivation переключается на случайное. Звук при переходе со старой версии включается один раз; последующее ручное выключение сохраняется (`soundDefaultsVersion: 2`). Safari разрешает звук только после действия пользователя.

## Большая сцена и финальные письма

Главный заголовок убран в пользу высокой сцены обсерватории: детализированный замок с часовой башней, горы, озеро с отражениями, каменная арка, витражные переплёты, плющ и парящие свечи. Сова, палочка и баночка — три независимых от текста способа открытия.

`final_001` и `final_002` не участвуют в случайных весах и очередях категорий. Только после чтения всех 156 остальных уникальных записок открывается первое, затем второе письмо — вне зависимости от выбранного настроения. После этого обычные циклы продолжаются, а финалы доступны в избранном. Эти письма автоматически сохраняются при естественном открытии, длинный текст прокручивается внутри отдельного оформления. Существующая история чтения учитывается, новые 50 записок тоже нужно прочитать для финала.


Релизная версия не содержит тестовых кнопок и обхода финала. Финальные письма проверяются автоматическими тестами с заранее подготовленным состоянием браузера, без добавления отладочных элементов в приложение.

## Как будет работать опубликованный подарок

GitHub Pages хранит готовые файлы сайта и отдаёт их браузеру по HTTPS. Локальный компьютер держать включённым не нужно, получателю не нужны Node.js и аккаунт GitHub. После обновления ветки main workflow пересобирает и публикует сайт, если в Settings → Pages выбран источник GitHub Actions. Статус публикации виден во вкладке Actions; успешный push сам по себе ещё не доказывает успешный deployment.

Для публичного репозитория GitHub Pages доступен на GitHub Free. Стандартный адрес github.io не требует покупки домена; платный тариф, сервер и API этому приложению не нужны. Фиксированного срока размещения по типу «30 дней» нет, но это не обещание вечного хранения: доступность зависит от аккаунта, репозитория, включённой публикации и условий сервиса. Сайт публичный; тексты доступны и в исходниках публичного репозитория.

Избранное и прогресс находятся в браузере получателя, а не на GitHub. Они сохраняются в том же браузере, пока его данные доступны, и могут не совпадать между Safari и Telegram. При очистке хранилища прогресс исчезнет.

Официальные условия: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages и https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits.

## Ошибка `Get Pages site failed / HttpError: Not Found`

Если ошибка возникает в `actions/configure-pages`, сначала откройте Settings → Pages → Build and deployment → Source и выберите **GitHub Actions**. Это однократное включение Pages; запуск workflow сам по себе не создаёт сайт. Для бесплатного аккаунта репозиторий должен быть публичным. Затем запустите **новый** запуск Publish GitHub Pages → Run workflow → main: повтор старого запуска использует старую версию workflow.

Не включайте `enablement: true` в надежде решить это штатным `GITHUB_TOKEN`: автоматическое создание сайта требует другого токена с дополнительными правами. Для обычной публикации после настройки Pages дополнительных секретов не нужно.

Workflow использует опубликованные версии Actions на Node.js 24 и образ Ubuntu 24.04. Предупреждения о старом runtime Node.js 20 и миграции ubuntu-latest не являются причиной ошибки отсутствующего Pages-сайта. Доступность сайта проверяется после успешного выполнения jobs build и deploy.
